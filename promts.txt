Перечислить вебсервис
		1. Общение с разными моделями нейросетей для генерации текста
			1. Можно использовать такие нейросети как:
				1. DeepSeek V3
				2. DeepSeek R1
				3. YandexGPT 5 Pro
				4. YandexGPT 5 Lite
				5. ChatGPT 4o mini
				6. ChatGPT 4o
				7. ChatGPT o1
				8. Qwen-Max
				9. Qwen-Turbo

		2. Хранение памяти о пользователе, чтобы нейросети могли использовать ее для генерации текстов
			1. Изменение памяти с помощью нейросети (Отсылается 2 сообщения, сначала изменение памяти, потом само сообщение, увеличивается стоимость генерации сообщения)
			2. Сам пользователь может указать что нужно в памяти. Он может редактировать ее или удалить
			3. Указать, нужно ли использовать память при общении с чатом или нет, для всех чатов, только для новых, или для конкретного чата
			4. При обновлении памяти происходит уведомление об этом
			5. Указание, возможно ли вообще изменять память при помощи нейросети
			6. Информация о памяти КОНФИДЕНЦИАЛЬНАЯ, поэтому она должна шифроваться

		3. Сохранение данных о сущностях в удаленной  базе данных

		4. Рублевый счет, который используется для генерации текстов
			1. Его возможно пополнять пользователю или админам
			2. Он тратится при генерации сообщения
			3. Все данные о денежных операциях сохраняются в бд (пополнение, трата на генерацию сообщений и системный сообщений)
			4. Если денег на счете не достаточно - генерация не происходит

		5. Возможность регистрации и входа через почту-пароль, с подтверждением почты

		6. Удобная навигация между созданными чатами, путем:
			1. Закрепления чата
			2. Чаты отсортированы сверху вниз по дате изменения чата
			3. Поиску чатов по названию чата

		7. Изменять настройки пользователя
			1. Могут ли чаты изменять память
			2. Использовать ли память в чатах новосозданных (в уже созданых чатах надо изменять самому)
			3. Пользователь может изменять память
			4. Поставить нейросеть, которая будет использоваться в новосозданных чатах
		
		8. Возможность изменять настройки уже созданого чата
			1. Изменять контекст чата
			2. Использовать ли память в данном чате
			3. Может ли данный чат изменять память
			4. Изменять модель для генерации текста
			5. Изменить температуру для генерации
			6. Закреплить ли данный чат или убрать из закрепленных
			7. Указать имя чата
			8. Удалить текущий чат

		9. Взаимодействие с сообщениями
			1. Поддерживается markdown разметка
			2. Возможно скопировать сообщение при помощи кнопки, и при помощи выделения
			3. Возможность перегенерировать сообщение, если ответ от нейросети не понравился (прошлый ответ не отображается пользователю, но сохраняется в бд)
			4. Можно изменить свое старое сообщение, чтобы получить ответ без сообщений после измененного сообщения (старые сообщения не отображаются пользователю, но сохраняются)
			5. В сообщениях хранятся эмбединги и их данные, которые позволяют сократить потребление денег при генерации Сервисы для реализации памяти

		10. Любой пользователь может пользоваться чат-ботами
			1. Чат ботов можно найти в магазине чат-ботов и использовать их
			2. В созданых чатах от чат-бота можно изменять настройки, но не все
		
		11. Можно создать чат-бота любому пользователю (и админу)
			1. Можно указать контекст чата
			2. Указать температуру чата
			3. Указать имя чата
			4. Указать приветственное сообщение
			5. Указать модель генерации для чата
			6. Может ли использовать память
			7. Может ли обновлять память
			8. Можно ли в созданых от этого чата изменять контекст чата
			9. Можно ли в созданных чатах изменять модель для генерации
			10. Возможность удалить чат-бота из магазина чатов пользователем или администратором
			11. Можно создать чат-бота через API интерфейс от администратора
			12. Можно указать тег чат-бота, что он выбран разработчиками

		12. Можно искать примеры чатов с помощью поисковика в магазине чатов, отображается список подходящих чатов. Если бар поиска пустой, то отображаются по популярности
			1. Популярность определяется по кол-ву сообщений, созданых за определенный сутки, обновляется раз в сутки
			2. Примеры чатов хранят кол-во сообщений, сгенерированных в чатах от этого примера
			3. Также отображается отдельный список чат-ботов выделенных разработчиками

		13. Приложений для пользователя будет 2
			1. Сайт, доступный с пк и телефонов
			2. Мобильное приложение

Связи между сущностями

<__> - Это слабая связь слева и справа у сущностей 
<<__> - Это сильная связь слева и слабая связь справа (сущность слева должна иметь сущность справа, а сущность справа не обязана). Также работает наоборо
<<__>> - Связи с двух сторон сильные
	1) Нейросеть 1:M Пользователь,  нейросеть <__>>  пользователь

	2) Пользователь 1:M чат,  пользователь <__>>  чат
	3) Чатбот 1:M чат,  чатбот <__>  чат
	4) Нейросеть 1:M чат,  нейросеть <__>>  чат

	5) Чат 1:M сообщение,  чат <__>>  сообщение
	6) Нейросеть 1:M сообщение, нейросеть  <__>>  сообщение

	7) Пользователь 1:M Чатбот, Пользователь <__> Чатбот
	8) Нейросеть 1:M Чатбот, нейросеть  <__>>  Чатбот

	9) Пользователь 1:M транзакция, пользователь <__>>  транзакция
	10) Пользователь 1:M транзакция, пользователь <__>  транзакция (для админов)
	11) Сообщение 1:M генерация, сообщение <__>> транзакция 

	12) Нейросеть M:1 Настройки,  Нейросеть <__>> Настройки
	13) Нейросеть M:1 Настройки,  Нейросеть <__>> Настройки (для генерации памяти)
	


Основные сущности и их взаимосвязи
1. Пользователь (AppUser)
	• Поля:
		○ id: long
		○ email: string (до 255 символов)
		○ uidFirebase: string (идентификатор из Firebase)
		○ role: string стандарт user (Есть роли user и admin)
		○ standartModelUriId: long 1:M Пользователь,  нейросеть <__>>  пользователь (связь с ModelUri, какая нейросеть будет использоваться для создания новых чатов)
		○ money:  DECIMAL (10, 4) (баланс в рублях)
		○ memory: string (хранит «память» пользователя, до 10 000 символов, КОНФИДЕНЦИАЛЬНАЯ ИНФОРМАЦИЯ)
		○ memoryEnabled: boolean (разрешено ли использоватьм память по умолчанию)
		○ aiCanUpdateMemory: boolean (может ли нейросеть изменять память)
		○ dateCreate: timestamp
2. Чат (Chat)
	• Поля:
		○ id: long
		○ userId: long 1:M чат,  пользователь <__>>  чат (связь с User)
		○ chatBotId: long 1:M чат,  чатбот <__>  чат (свзяь с ChatBot, может быть null. Стает null, когда чат-бот удаляется)
		○ modelUriId: long 1:M чат,  нейросеть <__>>  чат (связь с ModelUri)
		○ chatName: string (до 255 символов)
		○ temperature: double (настройка генерации сообщений)
		○ context: string (контекст чата, до 10 000 символов)
		○ starredChat: boolean (закреплён ли чат)
		○ canUseMemory: boolean (может ли чат использовать память, этот параметр не может изменить пользователь, от него зависит параметр useMemory)
		○ canUpdateMemory: boolean (может ли чат обновлять память, этот параметр не может изменить пользователь, от него зависит параметр updateMemory)
		○ canEditModelUri: boolean (можно ли в данном чате менять модель генерации. Присваивается значение от чатбота, а так при создании чата всегда true, этот параметр не может изменить пользователь)
		○ canEditContext: boolean (можно ли изменять контекст. Присваивается значение от чатбота, а так при создании чата всегда true, этот параметр не может изменить пользователь)
		○ useMemory: boolean (использовать ли память в данном чате)
		○ updateMemory: boolean (может ли чат изменять память)
		○ dateEdit: timestamp
		○ dateCreate: timestamp
3. Сообщение (Message)
	• Поля:
		○ id: long
		○ chatId: long 1:M сообщение,  чат <__>>  сообщение (связь с Chat)
		○ modelUriId: long 1:M сообщение, нейросеть  <__>>  сообщение (связь с ModelUri, нейросеть используемая для генерации сообщения)
		○ еmbedding: float[] (Эмбединг данного сообщения, нужен для уменьшения затрат на генерацию в базу данных Сервисы для реализации памяти , может быть null пока не сгенерируется или для сис. сообщения)
		○ oldMessage: boolean (Заменено ли это сообщение на новое, например при перегенерации сообщения или стерении сообщений. Если true, то это сообщение не отображается пользователю)
		○ role: string (тип сообщения, например, от пользователя или нейросети)
		○ text: string (текст сообщения, до 10 000 символов)
		○ type: string (тип сообщения, SystemMemory, User. Пользователю отображается только User в сообщениях)
		○ dateCreate: timestamp
		
4. ЧатБот (ChatBot)
	• Поля:
		○ id: long
		○ userId: long 1:M Чатбот, Пользователь <__> Чатбот(связь с User, может быть null)
		○ modelUriId: long 1:M Чатбот, нейросеть  <__>>  Чатбот (связь с ModelUri, нейросеть используемая для генерации сообщения) 
		○ chatBotName: string (название чатбота)
		○ chatBotDesc: string (Описание чата, то что пользователь может увидеть о чате)
		○ helloMessage: string (Приветственное сообщение при создании чата от чат-бота)
		○ isSelectedByRedact: boolean (Выбран ли чат редакцией для рекомендации)
		○ temperature: double
		○ context: string (контекст чатбота, до 10 000 символов)
		○ canUseMemory: boolean (Этот параметр нельзя поменять в конечном чате)
		○ canUpdateMemory: boolean (Этот параметр нельзя поменять в конечном чате)
		○ canEditModelUri: boolean (Этот параметр нельзя поменять в конечном чате)
		○ canEditContext: boolean (Этот параметр нельзя поменять в конечном чате)
		○ dateEdit: timestamp
		○ dateCreate: timestamp

5. Нейросеть (ModelUri)
	• Поля:
		○ id: long
		○ name: string (Название нейросети, которое видно пользователю)
		○ systemName: string (Системное название нейросети)
		○ desc: string (Описание для нейросети)
		○ costRequestRub:  DECIMAL (10, 4)(Расценка нейросети за 1 запрос, может быть null)
		○ costInputTokensRub:  DECIMAL (10, 4)(Цена за 1к токенов входящих, может быть null)
		○ costOutputTokensRub:  DECIMAL (10, 4)(Цена за 1к токенов выходящих, может быть null)
		○ maxOutputTokens: int (Максимальное кол-во выходных токенов при генерации)
		○ maxContext: int (Кол-во токенов, которые может обработать данная нейросеть)
		○ minRubles: DECIMAL (10, 4) (Минимальное кол-во денег на счете, чтобы возможна была генерация)
		○ ruleGeneration: string (Правила, которые используются для генерации)
		○ isUsingRules: boolean (Используются ли правила для данной нейросети)
		○ dateEdit: timestamp
		○ dateCreate: timestamp
6. Транзакция (PaymentTransaction)
	• Поля:
		○ id: long
		○ userId: long 1:M транзакция, пользователь <__>>  транзакция (связь с User, у кого изменяется счет)
		○ iniciatorUserId: long 1:M транзакция, пользователь <__>  транзакция (связь с User , тот кто иницировал с ролью администратора эту транзакцию, может быть null)
		○ messageId: 1:M генерация, сообщение <__>> транзакция (Связь с сообщением)
		○ changeMoneyRubles: DECIMAL (10, 4) (изменение баланса, положительное или отрицательное значение)
		○ inputTokens: int (может быть null если операция от инициатора, а не генерации)
		○ totalTokens: int (может быть null если операция от инициатора, а не генерации)
		○ cost: DECIMAL (10, 4) (стоимость генерации сообщения без учета комиссии, может быть null если операция от инициатора, а не генерации)
		○ costComission: DECIMAL (10, 4) (стоимость генерации сообщения с учетом комиссии, может быть null если операция от инициатора, а не генерации)
		○ type: string (Пополнение, Снятие, Генерация сообщения, Системное, Эмбединг)
		○ desc: string (описание операции)
		○ dateCreate: timestamp
7. Настройка приложения (AppSettings)
	• Поля:
		○ id: long
		○ standartModelUriId: long 1:1 Настройки, Нейросеть <__>> Настройки (Ссылка на ModelUri, какая модель для генерации будет поставлена любым новым пользователям)
		○ standartModelUriMemoryId: long 1:1 Настройки, Нейросеть <__>> Настройки (Ссылка на ModelUri, какая модель для генерации будет использована для обновления памяти)
		○ messageCostComissionAmpl: double (Мультипликатор для стоимости сообщений, чтобы вычислять комиссию с каждого сообщения)
		○ systemMessageCostComissionAmpl: double (Мультипликатор для стоимости системных сообщений, чтобы вычислять комиссию с каждого сообщения)
		○ startMoneyRub: double (Стартовое значение рублей при создании нового аккаунта)
		○ appGenerationRules: string (Правила для генерации во всех чатах. Указывается в контексте.)
		○ isUseGenerationRules: boolean (Используются ли правила для генерации во всех чатах)
		○ dateCreate: timestamp

Начинаем с самого начала, описание всех действий пользователя, которые он может сделать

	1) Проверка актуальности токена авторизации
		a. При заходе на сайт пользователя, отсылаем токен авторизации на бэк для проверки его актуальности
			i. Если токена нет, переход на экран входа
			ii. Если токен не подтвердился на бэке, получаем ответ, что токен просрочен и перенаправляем пользователя на экран входа
		b. Если токен верный, то перенаправляем пользоватлея на главный экран и получаем нужные данные (список чатов, нейросетей и информацию о пользователе)
		
	2) Регистрация пользователя (без подтверждения почты)
		a. Отправляем запрос на бэк на регистрацию нового пользователя. 
			i. Если ошибка, то уведомление о ошибке с возможностью зарегистрироваться заново
		b. Получаем положительный ответ от бэка, уведомляет, что пользователь зарегистрирован, переводит на страницу вход

	3) Вход пользователя
		a. Отправляем запрос на бэк на вход пользователя. 
			i. Если ошибка, уведомление о ней с возможностью зарегистрироваться
		b. Получаем положительный ответ от бэка, пользователя переводит на главную страницу
		c. Также делаем запросы на нужные данные с базы данных (список всех чатов пользователя (в будущем добавлю пагинацию) с полной информацией о каждом чате, информация о пользователе (считая id, без uidFirebase), список нейросетей и их информация)

	4) Нажатие на кнопку "Открыть список чат-ботов" (в будущем добавлю пагинацию)
		a. Открывается боковая панель списка чат-ботов, он загружается
		b. Отправляем на бэк запрос на список всех существующи чат-ботов 
			i. Идет проверка на доступ пользователя по JWT токену. Если не прошло, выводит ошибку пользователю
			ii. Если в ответе произошла ошибка, выводим ошибку в снекбаре и список чат-ботов пустой, если список пришел пустой, то просто список чат-ботов пустой, загрузка завершается
		c. Если успешный ответ, то загрузка проходит, выводим список чат-ботов (id, название, описание, кол-во сообщений за день) по популярности в столбке популярные, и в столбце выбрано редакцией те, что выбраны. Те что в выбраны не могут быть в популярном. Каждый чат-бот в этом списке отображает кол-во сообщений к этому чат-боту за день
		d. Состояние обновляется каждый раз при нажатии кнопки. Если в поиске чат-ботов было что-то написано, это сохранится, но список чат-ботов обновится
		e. В открытом виде кнопка заменяется на кнопку закрытия чат-ботов

	5) Нажатие на кнопку "Описание чат-бота"
		a. Открывается виджет с описанием чат-бота, он загружается
		b. Отправляем на бэк запрос на подробное описание конкретного чат-бота
			i. Идет проверка на доступ пользователя по JWT токену. Если не прошло, выводит ошибку пользователю
			ii. Если в ответе произошла ошибка, выводим ошибку в виджете и снекбаре, загрузка завершается
		c. 			iv. Сообщения, которое попросили перегенерировать и все после него, становится old, база данных отсылает бэку список нужных сообщений полученных по эмбедингу (кроме old сообщений) сообщения пользователя перед старым сообщением
		b. Бэк отсылает запрос на генерацию текста
			i. При других ошибках все также выводит ошибку пользователю
		c. Сохраняем ответ в бд вместе с транзакцией
			i. Если кол-во денег стало меньше нуля, выводится ошибка пользователю и отправляем ему сообщение
			ii. При других ошибках все также выводит ошибку пользователю.
		d. Генерируем эмбединг сообщения от нейросети
			При других ошибках все также выводит ошибку пользователю
		e. Сохраняем эмбединг в бд вместе с транзакцией
			i. Если кол-во денег стало меньше нуля, выводится ошибка пользователю и отправляем ему сообщение
			ii. При других ошибках все также выводит ошибку пользователю.
		f. Отправляем ответ от нейросети и обновленный баланс пользователю, если обновлена

	20) При нажатии на кнопку удалить все до этого сообщения пользователя
		a. Запрос на бэк на удаления сообщений
			i. Идет проверка на доступ пользователя по JWT токену. Если не прошло, выводит ошибку пользователю
			ii. Все сообщения до выбранного становятся old, эти сообщения пользователю не выводятся, база данных отсылает обновленный список сообщений
		b. Пользователь получает обновленный список сообщений чата
